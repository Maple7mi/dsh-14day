# 14 天学会 DeepSeek Harness

**写给高中毕业生的零基础计划 · 2026 年 11 月版 · 基于 DSH 桌面版 0.2.1-rc.5**

这份计划写给**没有编程基础**的人：每天 60–90 分钟，14 天，从"把 DSH 当成高级聊天框"到"能让 AI 自己读文件、写文档、查资料、组队干活，并交付一件拿得出手的作品"。

你不需要先学编程。DSH 是**工具**，就像学用 Word 不需要先会写小说；你负责"说清楚要什么、验收结果"，敲命令、写代码这些活交给它。

> 你之前那份《14 天 GitHub 学习计划》练的是"人和代码仓库打交道"。这份计划练的是"人和 AI 助手打交道"——2026 年最值钱的一项能力。两份计划不会冲突：第 13–14 天你会把它们合起来用。

## 三个问题，先给答案

你在需求里点名要的三件事，后面都有专门的天数和附录；但先给"一句话版"，让你带着地图走路。

**Q1：提示词到底怎么写？**
提示词不是"咒语"，是**工作交办单**。一张合格的交办单有六格：目标（要什么）、背景（给谁、为什么）、输入（哪些文件/数据）、约束（不许做什么、什么风格、多长）、验收（怎么算完成）、输出格式（写成什么）。写清楚这六格，普通模型也能干出专业活；缺了验收和输出格式，再强的模型也只能猜。→ 第 3–5 天系统练，附录 A 有 12 个可复制模板。

**Q2：什么叫 Agent Team？**
普通对话是"你和一个 AI 助手"，Agent Team 是"**你带一个项目组**"：一个 Lead（主智能体，就是你在聊的这个）加上若干有名字、有职责的 teammates（队友），它们共享同一块任务板，可以互相发消息、认领任务、按依赖排队，你只负责定目标和验收。它适合"需要几个人分头干、又不能把上下文的细节全塞进一个对话"的活。→ 第 9–10 天亲手组一次，附录 B 是完整手册。

**Q3：自带插件有什么内容？**
DSH 的本体（dsh-base + web-app）一共几百个包，但摆在你面前的其实是四类东西：**界面功能**（会话树、右侧文件/终端/浏览器、交付卡片…）、**能力工具**（读写文件、跑 PowerShell、搜索、定时提醒、Office 文档…）、**协作与扩展**（子代理、Agent Team、Workflow、技能、MCP、插件市场）、**实验功能**（语音输入、自动审查、会话检查器…）。→ 第 6、12 天带你逛，附录 C 是分组目录。

## 第 1 天：认识 DSH——它不是聊天框，是"会动手的助手"

### 今日目标

分清"聊天 AI"和"Agent（智能体）"；认识工作区、会话、模型、权限四样东西；完成第一个有交付物的任务。

### 核心概念

💡 **普通聊天 AI**：你问，它答，回答完就结束。它只能"说"，不能"做"。

💡 **Agent（智能体）**：能**用工具**的 AI。它能读你电脑上的文件、写文件、运行命令、上网查资料，做完还告诉你做了什么。DSH 就是一个 Agent 的工作台。类比：聊天 AI 是电话咨询，Agent 是上门干活的师傅。

💡 **工作区（Workspace）**：磁盘上的一个项目文件夹，比如 `E:\AI-Learning`。DSH 侧边栏按工作区分组；一个工作区里可以有无数个会话。**会话按创建时的目录归属，不能搬到别的工区**。

💡 **会话（Session）**：一次任务的对话记录。可以重命名、置顶、**分支（Fork）**、**归档**；DSH 不删会话，归档只是从列表隐藏，可以恢复。

💡 **模型**：干活的大脑。本机默认 `deepseek-flash`（快、便宜），难任务可以在输入框的模型菜单里换更强的模型、调推理等级。

💡 **权限（Permissions）**：决定 DSH 能对你的电脑做什么。三档：**仅可查看**（只读，只看不改）、**工作区内修改**（只能动当前工作区，写之前弹审批）、**完全权限**（什么都能做，不弹审批）。本机默认是完全权限，方便但危险，第 2 天细讲。

### 动手步骤

**第 1 步：逛一遍界面（10 分钟）**

打开 DSH 桌面应用（或浏览器访问 `http://127.0.0.1:13189`），对照着找：

| 位置 | 是什么 | 你会用它做什么 |
|---|---|---|
| 左侧边栏 | 工作区 + 会话列表 | 新建/切换会话、搜索历史、归档 |
| 中间 | 对话区 | 输入任务、看工作过程、看交付卡片 |
| 右侧边栏 | 文件 / 终端 / 浏览器 / 文档预览 | 看 DSH 改了哪些文件、预览 Word/PDF |
| 输入框下方 | 模型、权限、计划模式等开关 | 切模型、看上下文已用、开计划模式 |
| 左下角设置 | 通用 / 模型 / 账号 / 插件 | 学费用、换权限、管插件 |

🖱️ 试着做三件事：把鼠标悬停在一条会话上（出现"…"菜单）；点开右侧边栏；在输入框输入 `/`（看斜杠命令列表，`Esc` 关掉）。

**第 2 步：建一个练习工作区（10 分钟）**

```powershell
# 在 PowerShell 里执行，或在 DSH 里直接让它做
New-Item -ItemType Directory -Force E:\AI-Learning\DSH练习 | Out-Null
New-Item -ItemType Directory -Force E:\AI-Learning\DSH练习\notes | Out-Null
cd E:\AI-Learning\DSH练习
git init
```

🖱️ 回到 DSH：左侧边栏 → **添加工作区** → 选择 `E:\AI-Learning\DSH练习`。然后在工作区行菜单里点"新建会话"。

> 这个练习工作区有自己的 `.git`，和 `E:\AI-Learning` 的仓库互不影响（父仓库会把它当成一个未跟踪目录，不影响使用）。

**第 3 步：第一次任务——只读，不改文件（20 分钟）**

在新会话里粘贴：

```text
你是我的学习助手。工作目录是 E:\AI-Learning\DSH练习。

任务（只读，不要修改目录里已有的任何文件）：
1. 列出这个目录里的文件，最多两层子目录；
2. 用一张表格说明每个文件可能是干什么的（按文件名和内容判断）；
3. 把结果写入 notes/day01.md，第一行写生成时间；
4. 最后用一句话告诉我：这个目录现在最适合用来做什么。

验收标准：notes/day01.md 存在；表格至少 3 行；没有创建多余文件。
如果目录是空的，直接告诉我"目录为空"，不要为了完成表格而自己创建一堆文件。
```

观察三件事：
1. 它**先说计划再动手**（你会看到"准备读取文件""准备写入文件"这类状态）；
2. 它**调用了工具**——每次工具调用都是一张可展开的卡片，点开能看到具体命令和输出；
3. 结束后有**改动文件卡片**和**交付卡片**（右侧可点开预览）。

**第 4 步：验收与收尾（10 分钟）**

```powershell
Get-ChildItem -Recurse E:\AI-Learning\DSH练习 | Select-Object FullName
Get-Content E:\AI-Learning\DSH练习\notes\day01.md
```

对照验收标准检查。然后回到会话列表：右键或"…"菜单 → **重命名**为「Day01 目录说明」→ **归档**。

✍️ **练习**：再开一个会话，让它把这个目录整理成"学习工作区"（建 `docs/`、`notes/`、`output/` 三个目录，各放一个 README 说明用途），验收后归档。

### 完成标准

- [ ] 能说出工作区和会话的区别
- [ ] 成功添加 `E:\AI-Learning\DSH练习` 为工作区，并在里面新建了会话
- [ ] `notes/day01.md` 已生成，内容符合要求（自己看过）
- [ ] 能指出界面上"工具调用卡片""改动文件卡片"在哪
- [ ] 知道三档权限分别是什么意思
- [ ] 会话已重命名并归档，侧边栏干净

### 常见坑

- ⚠️ **在错误的工作区开会话**：会话归属创建时的目录，发现错了就归档重开，别想着搬。
- ⚠️ **以为"归档=删除"**：归档只是隐藏，随时能在视图选项里恢复；DSH 不做删除。
- ⚠️ **提示词太短**（比如"整理一下"）：模型只能猜，结果必然跑偏。今天先体会，第 3 天系统解决。
- ⚠️ **不看工作过程只看结果**：结果错了却不知道为什么。**点开工具卡片**是新手最快的进步方式。

📋 今日提示词模板（复制改括号）：

```text

任务：[一句话说清要做什么]。
只读/可以修改：[明确]。
输入：[哪些文件或数据]。
产出：[写到哪个文件，什么格式]。
```

## 第 2 天：Agent 怎么工作——工具循环、权限、上下文、成本

### 今日目标

看懂 DSH 的"工作过程"；亲手体验权限与审批；理解上下文为什么会越用越贵，学会三个省钱的习惯。

### 核心概念

💡 **工具循环（Tool Loop）**：Agent 干活的节奏是"想 → 做 → 看结果 → 再想"，循环直到完成。每一步它只能做一件小事：读一个文件、跑一条命令、搜一次网页。**它看不见的东西，它就不能用**——所以你要把路径、文件、背景告诉它。

💡 **沙箱（Sandbox）**：DSH 动手时被"关在笼子里"，笼子的范围由权限决定。只读笼子最大，完全权限没有笼子。**沙箱不是杀毒软件**，它只管"能不能写"，不管"写得对不对"。

💡 **审批（Approval）**：在「工作区内修改」档位下，DSH 要写文件/跑命令前会弹卡片等你点允许。这是你的**安全检查点**：看清它要干什么再点。

💡 **上下文（Context）**：模型每次回答前，DSH 都会把"系统提示 + 全部历史 + 工具结果"重新发给模型。对话越长，每次要读的越多。类比：每句话都要把整本会议记录重读一遍。

💡 **压缩（Compaction）**：对话太长时 DSH 会自动把早期内容总结成摘要，让对话能继续。本机窗口约 100 万 token，用到约 80% 时触发自动压缩（触发线 = `min(窗口×80%, 窗口 − 输出上限 − 64K)`）；也可以手动 `/compact`。**压缩有代价**（要花一次大请求），所以最好在它触发前主动分段。

💡 **缓存与价格**：重复发的前缀命中 DeepSeek 上下文缓存，按约 2% 的价格计费。所以"新开会话"不贵，"每步都背着几十万 token"才贵。本机 `deepseek-flash` 参考价（元/百万 token，空闲时段）：缓存命中 0.02、未命中 1、输出 4；高峰时段翻倍。以"设置 → 账号"里的实际用量为准。

### 动手步骤

**第 1 步：完整观察一次任务（15 分钟）**

在 `E:\AI-Learning\DSH练习` 新开会话，粘贴：

```text
工作目录 E:\AI-Learning\DSH练习。
任务：给我写一份「DSH 学习第一周计划」，要求：
```

## 第 3 天：提示词基础——把"帮我弄一下"变成"一次做对"

### 今日目标

掌握交办单六要素，能判断一条提示词为什么失败、怎么改。

### 核心概念

💡 **提示词 = 工作交办单**。你给实习生写交办单时不会只写"把那个弄一下"；对 AI 也一样。

💡 **六要素**（记住这六个词，比背一百个技巧有用）：

| 要素 | 回答的问题 | 例子 |
|---|---|---|
| **目标** | 最终要什么 | "写一篇 800 字的科普短文" |
| **背景** | 给谁看、为什么做 | "给高一学生看，放在学校公众号" |
| **输入** | 依据什么材料 | "参考 `notes/ai-notes.md`，只用里面的数据" |
| **约束** | 不许做什么、什么风格 | "不许用专业术语；不许编造数据；控制在 800 字" |
| **验收** | 怎么算完成 | "三个小标题；每个观点有例子；读完能回答'AI 为什么会犯错'" |
| **输出格式** | 写成什么样 | "Markdown，存到 `output/ai-intro.md`" |

💡 **模型不会"读心"，只会"填空"**。你少写一格，它就用自己的想象填——这就是为什么"帮我写个总结"总会给你一堆正确的废话。

💡 **具体 > 抽象**：把"写得好一点"换成"每段不超过 3 行，用 2 个具体例子"；把"参考一下资料"换成"只参考 `docs/` 下这两个文件"。

💡 **一次只交办一件事**：一条提示词里塞 5 个任务，它会漏掉 2 个。宁可分 3 条发。

### 动手步骤

**第 1 步：先看坏例子，再看差别（10 分钟）**

## 第 4 天：提示词进阶——@文件、先计划、会反问、会返工

### 今日目标

学会四种"高手动作"：用 `@` 精确投喂文件、用计划模式先审方案、让 DSH 反问你、用返工话术精准纠偏。

### 核心概念

💡 **`@` 引用**：在输入框输入 `@`，可以从候选菜单里选**文件、文件夹、会话或子智能体**。它的作用是把**路径作为引用**挂到这条消息里——模型看到的是"这份文件在这儿"，需要时**自己调用工具去读**。所以它省 token（不塞全文）、读到的永远是最新版本；而且 DSH 会给模型加一句约束：没读过就不许说"我看过"。

💡 **计划模式（`/plan`）**：让 DSH **只出方案不动手**。它会探索文件、写出完整计划，你审批通过后它才开始执行。适合"改动大、怕它乱来"的任务。审批时你可以直接驳回并写意见，它会改。

💡 **反问（ask_user_question）**：好的助手在动手前会问关键问题。DSH 有这个工具，会弹出选项让你点。**你可以在提示词里强制它反问**："如果信息不够，先问我，不要猜。"

💡 **返工话术**：结果不满意时，**别重发整段任务**，而是指出具体问题 + 划定修改范围 + 要求跑验收。句式：`上一轮的问题是[X]。只修 X，不要改动其他部分；修完把[验收命令/检查清单]的结果贴出来。`

💡 **会话的寿命**：同一个任务的迭代，**留在原会话**（上下文还在，不用重讲）；任务换了阶段、上下文已经很大，就**先让它写交接文件**，再新开会话。

## 第 5 天：让 DSH 记住你——AGENTS.md 与工作区结构

### 今日目标

给 DSH 建一套"员工手册"，让它每次开新会话都自动知道你的规矩；学会用文件而不是聊天记录来管理长期信息。

### 核心概念

💡 **AGENTS.md = 员工手册**。它放在你的项目里，**每次会话的第一个请求都会自动被读进去**。写"长期不变的规则"，不要写"今天的任务"。

💡 **加载规则（很重要）**：DSH 会按顺序找——
1. `~/.dsh/AGENTS.md`（你的全局规则，所有项目生效）
2. `~/.agents/AGENTS.md`（共享配置）
3. 从**项目根**到**会话工作目录**每一层的 `AGENTS.md`、`CLAUDE.md`、`AGENTS.local.md`、`CLAUDE.local.md`

**项目根 = 最近的包含 `.git` 的上级目录**；如果一路找不到 `.git`，项目根就等于会话工作目录（也就是说，父目录的 AGENTS.md 不会被加载）。总预算 64KB，越具体的越优先。

💡 **`docs/` 三件套**：`spec.md`（需求与设计，唯一真源）、`progress.md`（进度板：做到哪、下一步、已知问题）、`decisions.md`（关键决策 + 理由）。它们回答"这个项目现在是什么状态"，比翻聊天记录可靠。

💡 **`tasks/`**：一个子任务一张单（目标/输入/产出/验收清单/结果）。**任务单让你和 DSH 都不用猜。**

💡 **文件是长期记忆，聊天是工作过程**。DSH 的会话可能归档、可能压缩、可能很长；文件不会。**重要结论一定落文件。**

### 动手步骤

**第 1 步：建项目骨架（10 分钟）**

在 `E:\AI-Learning\DSH练习` 新开会话，用计划模式（或直接）发：

```text
工作目录 E:\AI-Learning\DSH练习。

任务：按下面的结构建好目录和空文件模板，已有文件不删不改：
```

## 第 8 天：子代理——把活分出去，别弄脏主对话

### 今日目标

理解"上下文隔离"为什么重要；会用子代理（subagent）并行做独立调研；知道它和 Agent Team 的区别。

### 核心概念

💡 **子代理（subagent）= 临时叫来的外援**。主对话把一件事交给它，它**自己开一个干净的上下文**去干，干完只把结果交回来。中间读了多少文件、试错了几次，**不会污染主对话**。

💡 **两种子代理**：
- **spawn（新建）**：给它一份任务说明，它从零开始，不看你之前聊过什么。适合"独立调研、独立实现"。
- **fork（继承）**：它继承你**已完成的对话**，适合"接着我刚才的思路往下做"。注意：fork 会把上下文一起带过去，更贵。

💡 **一次性 / 可继续**：子代理跑完会给你结果；如果还想要更多，可以再给它发消息继续（在右侧的"子智能体"面板里能看到每次的会话记录）。

💡 **什么时候用**：任务可以**独立完成 + 结论可压缩成一段话**。例如：读 5 个文件各写摘要、并行查 3 个主题、让另一个"人"审查你写的文档。

💡 **什么时候不用**：任务很小（自己两分钟就做了）、强依赖中间过程（每一步都要你拍板）、需要频繁改同一批文件。

## 第 9 天：Agent Team（上）——什么叫"带一支 AI 项目组"

### 今日目标

### 核心概念

💡 **Agent Team = 一个 Lead + 若干具名队友**。你现在聊天的这个会话就是 **Lead（主智能体）**。它可以创建队友（teammate），队友有自己的名字（例如 `researcher`、`writer`）、职责和**独立的持久会话**。

💡 **和子代理的区别**（这是今天最重要的理解）：

| | 子代理 subagent | Agent Team |
|---|---|---|
| 生命周期 | 一次任务，回来就结束 | **持久**：可被唤醒、可继续干、可跨多轮 |
| 通信 | 只跟主对话 | **成员之间可以互相发消息**，也能找 Lead |
| 任务管理 | 没有 | **共享任务板**：任务、依赖、认领、完成 |
| 适合 | 独立、一次性的活 | 多人分工、要协调、要反复沟通的活 |

💡 **共享任务板（Team Task Board）**：团队的中心。每个任务有标题、详情、**依赖（blocked_by）**、**写入范围（write_scopes）**、负责人（owner）。只有依赖都完成，任务才"可开始"；成员认领后才算"进行中"；完成、释放、重开都要改状态。

💡 **写入范围（write_scopes）只是提醒**：它标出"这个任务预计改哪些文件"，两个进行中的任务范围重叠时会提醒，但**不会阻止**任何操作。真正的安全靠你分配任务时**一个文件只给一个人**。

💡 **成员状态**：`running`（正在干）、`inactive`（没在跑，不等于干完了）、`provisioning`（正在创建）、`failed`（创建失败）。**inactive 不代表任务完成**——要看任务板和它的产出。

💡 **只有 Lead 能做三件事**：创建队友、指派/转派任务、中断队友。队友之间可以互相发消息，但不能建人。

💡 **本机限制**：最多 8 个队友；任务板最多 256 个活动任务；单条消息最大 64KB；**所有成员共享同一个目录**（没有隔离、没有文件锁、没有自动合并）；**不支持嵌套团队**；名字永久不复用；**任务 owner 不会自动释放**（队友挂了任务还挂在它名下，需 Lead 改派）。

## 第 11 天：Workflow——用脚本指挥一群 AI

### 今日目标

理解 Workflow 和 Subagent / Agent Team 的分工；让 DSH 写一个 workflow，对多个文件做批量审查。

### 核心概念

💡 **Workflow = 一段 JavaScript 编排脚本**。你在对话里描述"要对 N 个对象做同一套处理"，DSH 写脚本并运行：脚本里可以并行、可以分阶段、可以让每个子代理返回**结构化结果**（schema 校验），最后汇总。

💡 **和 Agent Team 的区别**：

| | Agent Team | Workflow |
|---|---|---|
| 谁决定下一步 | Lead 和队友临场判断 | **脚本预先写死** |
| 适合 | 需要商量、返工、分工协作 | **批量、重复、可流水线**的活 |
| 结果 | 文件 + 对话 | **结构化 JSON**，可继续加工 |
| 可预测性 | 低（灵活） | 高（稳定） |

💡 **常用能力**：`agent(prompt)` 起一个子代理；`parallel([...])` 并发；`pipeline(items, stage1, stage2)` 流水线；`phase()` 分阶段进度；`log()` 打日志；`args` 传参；返回可序列化的结果。

💡 **什么时候用**：审计 30 个文件、批量改写标题、对 10 个网页做多角度研究、迁移代码。**重复 N 次、每次差不多**的活，用 workflow 比开团队便宜且稳定。

### 动手步骤

**第 1 步：先跑一个小的（20 分钟）**

在 `E:\AI-Learning\DSH练习` 新会话，粘贴：

```text

请用 workflow 工具，对 notes/ 和 output/ 下所有 .md 文件做一次批量审查：
- 每个文件一个子代理，检查四件事：标题层级是否从 # 开始且不跳级、是否有连续空行、是否有明显错别字、字数；
- 并行处理，每个子代理只返回 JSON：{file, issues:[...], words}；
- 最后汇总成 output/audit-report.md：一张总表 + 按严重程度排序的问题清单。
- 运行前先把脚本给我看（打印出来），我确认后再跑。
```

它会把 workflow 脚本打印出来。**读懂三个部分**：
1. `meta`（名字、描述、阶段）；
2. 主体：怎么拿到文件列表、怎么 `parallel`、每个 agent 的 prompt 和 schema；
3. 返回值：汇总成什么。

**第 2 步：加一个阶段（15 分钟）**

### 常见坑

- ⚠️ **让 workflow 干"需要商量"的活**：它不会临场变通，剧本写完就按剧本走。
- ⚠️ **文件太多一次跑**：几十个并发子代理会烧钱且容易超时。**先 3–5 个试跑**。
- ⚠️ **不要求 schema**：结果变成一堆散文，没法汇总。**要求 JSON + 固定字段**。
- ⚠️ **忘了审查脚本**：脚本是代码，跑之前让它打印出来看一眼（有没有删文件、改原文件）。
- ⚠️ **把 workflow 当聊天**：它不回你消息，只返回结果；要交互就用 Team 或直接对话。

## 第 12 天：插件进阶——市场、实验功能、写一个自己的技能

### 今日目标

把插件页真正用起来：分清"装了什么"和"这个会话能用什么"；认识实验功能的代价；亲手写一个技能，让 DSH 以后按你的规程干活。

### 核心概念

💡 **插件页管"这台机器装了什么"，预设管"这个会话能用什么"**。DSH 把大部分工具从全局层"搬进了"每个会话的 agent 预设（standard / ptc / minimal）。所以会出现：插件页看不到 `tool-web` 的开关，但会话里 `web_search` 能用；或者某行显示已启用、会话里却没这个工具——**它不在当前预设里**。

💡 **插件页能做的六件事**：看组合包和每一行 → 开关组合包 → 开关某一行 → **添加插件**（包名 / Git / 压缩包 / 本地路径）→ 配（官方配置页：子智能体、网页搜索、Agent 循环、终端）→ 卸载。**实验性插件**单独一组，带"实验性"标签。

💡 **插件市场（Discover）本机默认没开**：它由 `dsh-experimental-plugin-market-bundle` 提供，不在本机启用的 bundle 里。想用要先在插件页的实验性分组里启用它，再"添加索引源"。注意：市场索引**没有签名**、**不支持一键升级**、只能装带 bundle 的包。

💡 **实验功能有代价**：
- **自动审查（Auto review）**：每次工具调用**多一次模型请求**，会明显变慢变贵，文档自己说可能误判——**先别开**，用"工作区内修改"权限更实在。
- **会话检查器（Inspector）**：会**未脱敏**采集网络请求，是排障工具，不是日常功能。
- **语音输入**：本地模型，首次要下载。
- **会话搜索 / Ralph / Worktree / 思维链翻译 / 持久终端工具**：本机都没启用，先知道有这回事。

💡 **技能（Skill）长什么样**：目录 `.dsh/skills/<名字>/SKILL.md`（或平铺 `<名字>.md`），开头是 YAML frontmatter：

```markdown
---
name: weekly-report
description: 当用户要写周报、学习总结或阶段复盘时使用。
---
（正文：这类活该怎么干——步骤、模板、检查清单）
```

规则：`name` 必须小写连字符；`description` 是模型判断"什么时候用"的唯一依据（目录里只显示名字和这句描述）；**只扫一层目录**，不支持嵌套；正文没有大小上限，但只在加载时进入上下文。写完**立刻生效**，不用重启。

💡 **定时提醒 / 后台任务**：定时提醒（Schedule）是"到点给原会话发一条消息"，适合"每天 21:00 提醒我复盘"；后台任务是"长命令丢后台跑，不用等"，两者都在会话头部/侧栏能看到、能停。

💡 **MCP**：把外部工具服务器（GitHub、文件系统、数据库……）接成 DSH 的工具。它是普通插件 + 配置，需要手写 `cordis.patch.yml` 的一行。**知道概念即可，第一次配置建议等你能看懂配置文件**。

14. Workflow 和 Agent Team 怎么选？
15. 说出 5 个自带功能，并说明各自解决什么问题。

**第 7 步：定下一个 30 天计划（10 分钟）**

3. **用 DSH 做内容**：把 14 天所学写成教程/视频脚本，发布到 GitHub + 平台，建立作品集。

### 完成标准

- [ ] 项目所有任务完成或明确取消，并写下原因

### 常见坑

- ⚠️ **验收只看它的汇报**：一定要自己打开文件看。它说"已完成"不等于完成。
- ⚠️ **发布前不检查隐私**：仓库一旦公开，历史里删不干净。
- ⚠️ **不导出会话**：换电脑/重装就只剩作品，没有过程记录。**过程也是作品的一部分。**
- ⚠️ **复盘写成流水账**：写"下次怎么做"才有用，写"我学了什么"只是给自己看。
- ⚠️ **做完就停**：14 天的价值在于形成习惯。**下一个 30 天，哪怕每天 30 分钟，也要持续产出。**

## 附录 A：提示词手册

### A1. 一条提示词的骨架

```text
[角色]（可选）
目标：……
背景：……
输入：……（路径/文件/链接）
约束：……（不许做什么、风格、长度、语言）
验收：……（可检查的标准）
输出：……（写到哪、什么格式）
```

**六格缺一格会怎样**（这是新手最容易踩的坑）：

| 缺了什么 | 模型会怎样 | 典型后果 |
|---|---|---|
| 目标 | 猜一个它以为的目标 | 做得很努力，但不是你要的 |
| 背景 | 用通用假设 | 内容空泛、对象错位 |
| 输入 | 凭训练数据编 | 数据过时或编造 |
| 约束 | 自由发挥 | 太长、跑题、动了不该动的文件 |
| 验收 | 不知道何时停 | 提前收工或过度加工 |
| 输出格式 | 只在对话里给你 | 关掉会话就找不到成品 |

### A2. 十条可操作原则

1. **先写目标与验收**：模型没有"完成"信号，验收必须由你说。
2. **给路径，不贴长文**：长文会作为历史反复计费；文件让模型自己读。
3. **一次只给一件可验收的事**：五件事混一轮，验收点互相稀释。
4. **写清边界**："只改 X，不要动 Y，需要越界先问我"。
5. **规定输出格式**：三段式（结论 / 证据 / 风险）比"分析一下"有用得多。
6. **先计划后执行**：大改动先 `/plan`，拿一个人类批准点。
7. **不确定就让它先问**：把"拿不准就问，给推荐项"写进提示词。
8. **返工说清"差在哪、改成什么"**：只指出问题、划范围、要验收结果。
9. **上下文卫生**：一个可验收的子任务一个会话；换阶段先写交接文件。
10. **用文件当记忆**：结论写进 `docs/`、`notes/`，不要指望对话记住。

### A3. 十二个可复制模板

**1）新建任务**

```text
工作目录：[绝对路径]。
目标：[一句话最终结果]。
背景：[给谁/为什么/什么基础]。
输入：[读哪些文件，不读什么]。
约束：只改 [范围]；不要动 [禁止清单]；[风格/长度/语言]。
验收：[可检查标准 1]；[标准 2]。
输出：[文件路径 + 格式]。
不确定时先问我（给推荐项和理由），不要猜。
```

**2）返工**

```text
上一版的问题：[具体到文件/段落，1–3 条]。
期望改成：[具体形态，最好给对照例子]。
保持不变：[不要顺手改的部分]。
只改这些；改完逐条对照验收标准复述结果。
```

**3）调研**

```text
问题：[一句话]。
范围：只查 [路径/文档/URL 列表]。
方法：先列证据，再给结论；每条结论后标 [文件:行] 或 URL。
不要：凭印象补细节；找不到就写"未找到"。
输出：结论 ≤3 条 + 证据表 + 仍不确定的点。
```

**4）写文档**

```text
读者：[谁看、什么基础]。
目标：读完能 [做到什么]。
结构：[小节标题列表]。
素材：只用手头的 [文件/链接]，不要编造。
风格：中文，术语保留英文并解释，代码块要能直接跑。
写到 [路径]；不要改其他文件；写完列出引用出处。
```

**5）审查代码/文档**

```text
审查对象：@[文件或目录]。
关注：[正确性/一致性/可执行性/与文档是否相符]。
产出：按严重度排序的问题清单，每条 = 位置 + 问题 + 建议改法。
先给清单，我挑完你再改；没问题的部分明确写"未发现问题"，不要凑数。
```

**6）交接换会话**

```text
先读 [notes/progress.md 或 docs/handoff.md]，那是上一段的结论。
当前目标：[一句话]。
已完成：[≤3 条]。
下一步：[一件事]。
约束：[已定死、不要再讨论的决定]。
先复述你理解的状态，再开工。
```

**7）先复述计划**

```text
动手前用 5 行以内回答：
1) 你要改哪些文件 2) 每处改什么 3) 怎么验证 4) 有哪些不确定。
我确认之前不要写文件、不要跑会改状态的命令。
```

**8）计划模式**

```text
/plan

工作目录：[路径]。
目标：[结果]。
现状：[已知文件/结构/限制]。
要求：[步骤约束，如"不删文件""只新建不改旧"]。
先探索再给计划：分步写清做什么、动哪些文件、怎么验证。
不要动手，等我批准；我驳回时按意见修改后重新提交。
```

**9）并行调研（子代理）**

```text
工作目录：[路径]。
用 [N] 个子代理并行完成以下调研，全部回来后再汇总：
- 任务 A：[目标/读什么/产出/格式]
- 任务 B：……
每个子代理写 output/research/[名称].md；
汇总成 [报告路径]，标注每节来源；不许编造。
```

**10）组建团队（Agent Team）**

```text
工作目录：[路径]。
用 Agent Team 完成 [目标]，产出 [文件]。

任务板：
- 任务 1：[内容] / owner [A] / 写入范围 [文件] / 验收 [标准]
- 任务 2：[内容] / owner [B] / 依赖 任务 1 / 写入范围 [文件] / 验收 [标准]
- 任务 3：审查 / owner [C] / 依赖 任务 1、2 / 产出 [问题清单]
- 任务 4：汇总 / owner Lead / 依赖 任务 3

规则：每个 owner 只写自己的文件；任务描述自包含（队友看不到我们的对话）；
你负责唤醒 inactive 队友、处理卡住的任务、按标准验收；
完成后汇报：任务板变更次数、问题清单、最终文件。
```

**11）批量处理（Workflow）**

```text
工作目录：[路径]。
用 workflow 对 [对象集合] 做 [同一套处理]：
- 每个对象一个子代理，prompt 自包含；
- 返回 JSON，字段固定：[字段]；
- 并行/分阶段：[编排方式]；
- 汇总成 [报告路径]。
运行前把脚本打印给我看；先只跑 [N] 个样本。
```

**12）定时/后台**

```text
帮我建一个 [每天 21:00 / 每周日 10:00 / 明天 9:00] 的提醒：
内容是"[提醒文本]"，我在这个会话里等它。
另外把 [长命令] 丢到后台跑，不要阻塞对话；跑完把结果摘要给我。
```

### A4. 好提示词 vs 坏提示词（对照）

| 坏 | 好 | 为什么 |
|---|---|---|
| 帮我整理一下文件 | 把桌面 `待整理/` 里的文件按"图片/文档/其他"分到三个子目录，生成一份清单到 `notes/整理清单.md`，不要删除任何文件 | 有目标、范围、产出、约束 |
| 写个总结 | 读 @docs/进度.md，写 200 字总结给没参与项目的人看，三段：做了什么/现在在哪/下一步 | 有读者、输入、结构、长度 |
| 优化一下代码 | 只改 `src/a.ts` 的 `parse()` 函数，让它处理空输入不报错；加一个测试；不要动其他函数 | 有范围、验收、边界 |
| 你觉得怎么办 | 给我 3 个方案，每个写清成本/风险/推荐理由，最后给推荐项 | 强制结构化输出 |
| 重做 | 第 2 段数据错了：2026 年不是 2025 年。只改这一处，其余保持 | 返工要具体 |

### A5. 反模式清单

- ❌ 把"要专业/要好看/要口语化"当要求 → ✅ 换成可数的标准（字数、段数、术语表、示例数）
- ❌ 一次塞五个任务 → ✅ 拆成五条，逐条验收
- ❌ 贴 300 行日志 → ✅ 给路径 + 让它切片读（"先读前 100 行，再 grep 关键字"）
- ❌ 不提验收 → ✅ 至少 2 条可检查标准
- ❌ 让它在对话里交付 → ✅ 要求写入文件
- ❌ 出问题就重开一轮 → ✅ 用返工句式在原会话修
- ❌ 以为改 AGENTS.md 会"替换"旧规则 → ✅ 它追加新消息，旧文本仍在历史里
- ❌ 以为 `@文件` 就把文件内容发给模型了 → ✅ 它只插入路径，模型要自己读
- ❌ 以为计划模式能阻止它动手 → ✅ 它只是文本约束，真正的护栏是权限 + 沙箱
- ❌ 以为问题超时没回答=默认同意 → ✅ 超时不等于批准

## 附录 B：Agent Team 手册

### B1. 一页看懂

| 概念 | 大白话 | 关键事实 |
|---|---|---|
| **Lead** | 你正在聊的这个会话，就是"队长" | 隐式存在，不需要创建；`TeamId` = 会话 ID |
| **teammate（队友）** | 有名字、有职责、有独立持久会话的 AI | 只能由 Lead 创建；名字永久、不复用 |
| **共享任务板** | 团队的白板，谁干什么、卡在谁那 | 任务有 owner、依赖、写入范围、revision |
| **inbox / 消息** | 队友的收件箱 | 消息会进目标的历史（带发送者名字前缀） |
| **写入范围 write_scopes** | "这个任务大概会改哪些文件" | **只是提示**：重叠只警告，不阻止 |
| **依赖 blocked_by** | "任务 A 没完成，任务 B 不能开始" | 依赖全部完成，任务才"可开始" |
| **revision** | 任务的版本号 | 每次变更都带版本，防止互相覆盖（旧版本操作会被拒） |

### B2. 工具清单

| 工具 | 谁可以用 | 作用 | 关键点 |
|---|---|---|---|
| `spawn_teammate` | **仅 Lead** | 创建一个具名队友 | 参数：`name`（小写连字符）、`description`、`prompt`（完整初始任务）、`context`（`fresh` 无记忆 / `fork` 继承已完成轮次） |
| `send_message` | 所有成员 | 给另一个成员发消息 | running 的目标在**最近的步骤边界**收到；inactive 的目标会被**唤醒**；返回"已入箱"，不代表已处理 |
| `list_agents` | 所有成员 | 看成员名册与状态 | 无参数；只反映"当前可寻址的成员与可用性" |
| `wait_agent` | 所有成员 | 等下一次团队变化 | 只观察**调用之后**的状态/message/任务变化；**不会唤醒**任何人；没有活跃成员时立即返回 noProgress；超时 10 秒–1 小时，默认 30 秒 |
| `interrupt_agent` | **仅 Lead** | 中断队友当前轮次 | **保留**它排队的消息；不释放任务 owner |
| `team_task_create` | 所有成员 | 创建待办任务 | 参数：`subject`、`description`、`blocked_by`、`write_scopes` |
| `team_task_list` | 所有成员 | 列任务 | 可按 `status`/`owner`/`ready` 过滤；`owner: "unowned"` 查无主任务 |
| `team_task_get` | 所有成员 | 读单个任务（含最新 revision） | 改任务前必须先读 |
| `team_task_update` | 所有成员（部分操作仅 Lead） | 改任务 | 必须带 `expected_revision`；`action`：claim / release / edit / set_dependencies / complete / reopen / **reassign（仅 Lead）** / delete |

> 本机配置：最多 **8** 个队友（默认上限 16）、**256** 个活动任务、单条消息 **64KB**。

### B3. 成员状态

| 状态 | 含义 | 你该做什么 |
|---|---|---|
| `provisioning` | 正在创建 | 等（它可能还在启动） |
| `running` | 正在执行一轮 | 别打扰；等结果或 `wait_agent` |
| `inactive` | **当前没有执行轮次**（可能在等消息，也可能干完了，也可能只是没被叫醒） | **先看任务板和产出**；需要它继续就 `send_message` |
| `failed` | 创建失败 | 名字已占用、不能复用；换名字重建或改派任务 |

> 记住一句话：**inactive ≠ 完成**。完成与否看任务板 + 文件。

### B4. 标准协作流程

1. **Lead 拆任务**：5–8 个，每个可独立验收；写清目标/输入/产出/验收/写入范围/依赖。
2. **建任务板**：`team_task_create`，有先后关系的用 `blocked_by`。
3. **创建队友**：`spawn_teammate`，prompt **自包含**（fresh 队友看不到你的对话）。
4. **派活**：任务指给 owner（`team_task_update` reassign），或让队友自己 claim。
5. **盯进度**：`list_agents` + `team_task_list`；队友 inactive 且任务没完成 → `send_message` 唤醒；有活跃队友时才 `wait_agent`。
6. **验收**：读产出，按验收标准逐条核对；不合格 → 返工（改任务/发消息）。
7. **收尾**：任务 complete；`docs/progress.md` 更新；Lead 给最终答案前必须等齐必需的队友。

### B5. 已知限制（重要，必须知道）

| 限制 | 影响 | 应对 |
|---|---|---|
| **单进程、共享同一目录** | 成员改的文件立刻互相可见；没有隔离、没有文件锁、没有自动合并 | **按文件/目录分工**；Lead 最后检查 diff |
| **写入范围只是提示** | 重叠只会警告，不会阻止覆盖 | 任务设计上避免重叠 |
| **扁平不可嵌套** | 只有 Lead 能建人；队友不能再建团队 | 任务分片，不要幻想"分队长" |
| **名字不可复用/不可删** | 失败的名字也永久占用 | 起名想清楚；失败就用新名字 |
| **owner 不会自动释放** | 队友挂了，任务还挂它名下 | Lead 用 reassign/claim 处理 |
| **没有发送重试/去重保证** | 进程崩了，未送达的消息不会补发 | 关键信息落文件，不靠消息 |
| **任务 CAS** | 基于旧 revision 的修改会被拒 | 改前先 `team_task_get` 拿最新 revision |
| **开销放大** | 每个队友都是独立上下文和独立计费 | 小任务别开团；2–3 人起步 |

### B6. 什么时候用 / 不用

**适合**
- 一个任务可以拆成 3–8 个相对独立的片（三个章节、三个页面、三个模块）；
- 需要"分工 + 串行依赖 + 审查"的流水线（调研 → 写作 → 审查）；
- 需要多个视角互相挑错（红队审查）；
- 任务跨多轮，队友的状态和产物需要保留、可恢复。

**不适合**
- 小而简单、一个人（单会话）20 分钟能做完的事；
- 必须频繁你来我往拍板的探索型任务（每次都要你决策，团队协调成本更高）；
- 多个成员必须改同一个文件（冲突几乎必然）；
- 你无法验收的任务（团队产出多，你判断不了对错就更危险）。

### B7. 一个完整示例

```text
工作目录 E:\AI-Learning\DSH练习。
用 Agent Team 做一个「DSH 学习指南」小册子（3 章 + 1 次审查），产出到 output/guide/。

1. 创建 4 个队友：writer-a、writer-b、writer-c、reviewer。
2. 任务板：
   - T1 第 1 章「认识 DSH」，owner writer-a，写入范围 output/guide/ch1.md；
     验收：800–1200 字、含 1 张表、含 3 个新手坑。
   - T2 第 2 章「提示词」，owner writer-b，写入范围 output/guide/ch2.md，同上。
   - T3 第 3 章「Agent Team」，owner writer-c，写入范围 output/guide/ch3.md，同上。
   - T4 审查三章，owner reviewer，blocked_by T1,T2,T3，写入范围 output/guide/review.md；
     验收：每章至少 2 条具体问题，不许直接改别人的文件。
   - T5 汇总，owner Lead，blocked_by T4，产出 output/guide/README.md（目录+摘要）。
3. 每个任务描述要自包含：素材只允许来自 E:\AI-Learning 下现有文档，不许编造。
4. 任一队友 inactive 且任务未完成，先 send_message 唤醒；没有活跃成员时不要空等。
5. 验收通过后向我汇报：任务板变更次数、reviewer 挑出几条、最终文件清单。
限制：两人不许写同一个文件；超过 8 个任务或出现重叠先停下来。
```

### B8. 新手常见误解（10 条）

1. "建了团队 AI 就会自动分工"——分工是 **Lead 的任务书**决定的，任务写得烂，团队就乱。
2. "队友是子代理的升级版"——队友是**持久**的、能互相通信的；子代理是一次性的。两者用途不同。
3. "inactive 就是完成了"——inactive 只表示"现在没在跑"。
4. "写入范围能防止冲突"——它只是提示，冲突要靠分工避免。
5. "队友能看到我们的对话"——默认 `fresh` 看不到，任务必须自包含；`fork` 才继承。
6. "Lead 可以下场写正文"——可以，但 Lead 的核心价值是拆解、协调、验收。
7. "任务改一下随便改"——任务板是版本化的，旧 revision 的修改会被拒绝。
8. "团队越大越好"——每个成员都在独立烧 token；2–3 人通常是性价比最高的。
9. "队友失败可以重名重建"——名字永久占用，失败也要换新名字。
10. "等不到就反复轮询"——`wait_agent` 观察变化、`list_agents` 看状态、`send_message` 唤醒，顺序别反。

## 附录 C：自带插件目录

### C1. 先理解三件事

1. **"包多"不等于"插件多"**：本机安装包里约有 306 个 npm 包，但你在界面上能感知的功能大约 40 项。绝大多数包是内部实现细节（文件系统、会话格式、沙箱、存储……），普通用户不需要认识。
2. **插件页管"这台机器装了什么"，预设管"这个会话能用什么"**：DSH 把大部分工具从全局层"搬进"了每个会话的 agent 预设（`standard` 默认 / `ptc` / `minimal`）。所以插件页看不到 `tool-web` 的开关，但会话里 `web_search` 照样能用。
3. **一句话口诀**：看得见的东西 → **插件页**；看不见但会用的工具 → **预设**；外部世界 → **MCP**；一次性的说明书 → **技能（skill）**。

### C3. 插件页怎么用（六件事）

| 动作 | 怎么做 | 注意 |
|---|---|---|
| 看 | 侧栏 **插件** → 已安装/实验性分组 | 点进组合包能看到它的每一行 |
| 开关组合包 | 卡片上的开关 | 写 `package.json` 的 bundle 列表；关闭不删依赖 |
| 开关某一行 | 组合包详情里逐行开关 | 只出现在已打开的组合包上；Host 不寻址的行锁定 |
| 装 | **添加插件** → 包名 / Git / 压缩包 / 本地路径 | 先 inspect 再 pnpm 安装；失败可重试/换源 |
| 配 | 本页"内置插件配置"分组：子智能体、网页搜索、Agent 循环、终端 | 配置页在插件页，不在设置里 |
| 卸 | 卸载并确认 | 随 DSH 发布的 bundle 只能关不能卸 |

**风险与回退**：改坏 `cordis.patch.yml` 可能让界面起不来——**改前先复制一份 `.bak`**，出事就还原。装插件失败时 Host 会自动恢复 `package.json` 和锁文件，但你的手写配置不会自动恢复。

### C4. 新手开关建议

- **第一天就用**：会话+工作区、右侧栏文件树/预览、`@` 与 `/`、交付/改动卡片、后台任务、定时提醒。
- **先把权限改回"工作区内修改"**：本机默认是完全权限且不弹审批，零基础用户不该在没有护栏时让 agent 跑命令。
- **想清楚再开**：插件市场（第三方代码）、会话搜索（模型侧搜历史）、会话标题变体。
- **先别碰**：自动审查（慢且贵）、Inspector（未脱敏）、Ralph/Worktree/思维链翻译、MCP、手改配置文件。

## 附录 E：上下文与成本管理清单

### E1. 先记住三个数字

| 数字 | 含义 | 对你的意义 |
|---|---|---|
| **1M token** | 本机上下文窗口 | 能装很多，但每步都要重发 |
| **约 80%** | 自动压缩触发线（≈ `min(窗口×80%, 窗口−输出上限−64K)`） | 别拖到自动压缩，它本身要花一次大请求 |
| **约 2%** | 缓存命中价 / 未命中价比 | "重读旧内容"便宜，但"每一步都背着大上下文"不便宜 |

参考价（`deepseek-flash`，元/百万 token，空闲时段）：缓存命中 0.02、缓存未命中 1、输出 4；高峰时段（工作日 9:00–12:00、14:00–18:00）翻倍。**以设置 → 账号里的实际用量为准。**

### E2. 十二条省钱习惯（建议打印贴墙）

- [ ] 一个**可验收的子任务**一个会话，验收完就归档。
- [ ] 同一任务的**返工留在原会话**；换阶段先写 `handoff.md` 再新开。
- [ ] 别把长文贴进对话——给**文件路径**，让它切片读。
- [ ] 大文件先 `grep` / 读前 100 行，不要整份读进对话。
- [ ] 长输出让它**写文件**，对话里只留摘要。
- [ ] 上下文过 10–20 万就 `/compact` 或换会话，别等 80%。
- [ ] 重活排到**晚上/周末**（错峰半价）。
- [ ] 简单任务在模型菜单里**降推理档**。
- [ ] 只有难题才切更强的模型。
- [ ] 独立调研/批量任务用**子代理 / Workflow**，别开一堆长会话。
- [ ] **别频繁改 AGENTS.md**：改了会追加新指令，旧规则还在历史里。
- [ ] 每天收尾更新 `docs/progress.md`，让下一次会话能"接上"而不是"重讲"。

### E3. 每周看一次用量

设置 → 账号 / 通用设置 → 性能与用量，重点看：
- 缓存命中率（越高越省）；
- 最长的几个会话（是不是该拆）；
- 高峰时段占比（能不能错峰）；
- 团队/子代理的花费占比（值不值）。

## 附录 F：常见错误急救

| 症状 | 最可能的原因 | 怎么修 |
|---|---|---|
| 界面打不开 / 一启动就报错 | 手改 `cordis.patch.yml` 写坏了 | 用备份的 `.bak` 还原；没有备份就删掉最近加的那几行 |
| 插件页关了东西，界面功能消失 | 关掉了界面插件 | 插件页重新打开；或还原 profile patch |
| 改了配置不生效 | 需要重启，或行被上层覆盖 | 重开会话/应用；确认改的是 profile 的 patch |
| 新会话里没有某个工具 | 它不在当前 agent 预设里 | 换预设（standard）或在预设编辑里加；这不是 bug |
| 技能没出现 | frontmatter 写错 / 目录层级错 | `name` 用小写连字符；文件放 `.dsh/skills/<name>/SKILL.md`，只扫一层 |
| AGENTS.md 没生效 | 工作目录不在项目根下 / 规则写得太抽象 | 确认 `git init` 的根；新开会话验证；把规则写成可执行句 |
| AGENTS.md 改了但旧规则还在 | 更新是"追加消息"，旧文本仍在历史 | 正常现象；新会话验证；别频繁大改 |
| 它说"做完了"但文件不对 | 没验收 | 打开文件看；用"验收清单"返工 |
| 团队队友不动 | inactive，或任务没派给它 | `list_agents` 看状态 → `send_message` 唤醒；检查任务 owner |
| `wait_agent` 立刻返回 | 没有活跃成员 | 先 `list_agents`，再用 `send_message` 唤醒需要的成员 |
| 任务 claim 失败 / 更新被拒 | revision 过期 | 先 `team_task_get` 拿最新 revision 再改 |
| 子代理结果找不到 | 它只回复了，没写文件 | 要求"结果写进 output/xxx.md" |
| 上下文已用很高、回答变笨 | 会话太长 | `/compact`，或写交接后新开会话 |
| 账单比预期高 | 巨型会话 + 长输出 + 高峰时段 | 见附录 E 的十二条习惯 |
| 网页搜索总失败 | 网络/额度/服务 | 查网络与账号余额；换 `web_fetch` 直接抓 URL |
| Word/PDF 打不开或乱码 | 生成失败或字体问题 | 让它检查并重新生成；PDF 用 Office 技能导出 |
| Pages 打开是 404 | 分支/目录设置不对 | Settings → Pages 检查 `main` + 目录；等 1–3 分钟 |
| 误删/改坏了文件 | 无版本控制 | 有 git 就 `git restore`；没有就只能重做——**这就是每天 commit 的理由** |

| 配置文件补丁 | profile patch | `cordis.patch.yml`，按 id 覆盖配置 |
| 子代理 | subagent | 独立上下文的临时外援 |
| 智能体团队 | Agent Team | Lead + 队友 + 共享任务板的协作机制 |
| 队长 | Lead | 当前会话，团队的协调者 |
| 队友 | teammate | 有名字、有职责、持久存在的成员 |
| 共享任务板 | task board | 团队的任务清单（含依赖/owner/写入范围） |
| 写入范围 | write scopes | 任务预计改哪些文件（只是提示） |
| 工作流 | workflow | 用 JS 脚本批量编排子代理 |
| MCP | Model Context Protocol | 接外部工具服务器的协议 |
| 交付物 | deliverable | 明确声明交给用户的文件 |
| 计划模式 | plan mode | 只出计划不动手，等你批准 |
| 缓存命中 | cache hit | 重复前缀按低价计费 |
| 推理等级 | reasoning effort | 模型思考档位，越高越慢越贵 |

   ```powershell
   git config --global user.name "你的名字"
   git config --global user.email "你的邮箱"
   git config --global init.defaultBranch main
   ```
4. 安装 GitHub CLI 并登录：`gh auth login`（HTTPS + 浏览器）；
5. 在 DSH 里重新注册工作区：侧栏 → 添加工作区 → 选 `E:\AI-Learning`；
6. 新建会话验证：AGENTS.md 是否生效、技能是否出现、`/export` 是否可用；
7. 重要配置备份：`C:\Users\你的用户名\.dsh\profiles\desktop\cordis.patch.yml`（手改过的配置）与 `~/.dsh/AGENTS.md`（全局规则）。
